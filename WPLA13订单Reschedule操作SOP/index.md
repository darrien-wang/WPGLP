## 2. 前一天订单Reschedule操作

**作业时间**: 13:15-13:30（固定时间段）  
**系统涉及**: OR系统、DMS系统  
**责任人**: 调度员

### 2.1 重要说明

- ⚠️ **仅处理前一天的订单**
- ⚠️ **不要重派当天的订单**（当天问题件还未返回仓库）
- ✅ **例外情况**：如果订单还在派送网点（未返回仓库），可以立即reschedule
  - 常见情况：商业地址关门
  - 确认方式：联系司机或查看订单状态，确认包裹位置
  - 操作方式：直接在OR系统进行reschedule，安排第二天配送

### 2.2 标准操作流程

#### 步骤1: 在OR系统中查找订单
1. 登录OR系统
2. 选择对应的配送地区
3. 搜索订单号
4. 如果找到订单，直接进行reschedule操作

#### 步骤2: DMS系统辅助查询（当OR中找不到订单时）
1. 登录DMS系统: https://dms.wpglb.com
2. 使用你的账号密码登录
3. 在DMS中搜索订单号
4. 查看订单的**线路信息**字段
5. 记录该订单的**配送日期**

#### 步骤3: 返回OR系统进行Reschedule
1. 返回OR系统
2. 进入"规划路线"页面
3. 选择从DMS查询到的**对应配送日期**
4. 输入订单号进行搜索
5. 找到订单后执行reschedule操作
6. **重要**：将旧的无效订单ID更新为-1（或-2、-3等）
   - OR系统不允许两个相同ID的订单同时存在
   - -1、-2、-3等负数ID代表历史派送记录
   - 这样可以保留历史记录同时允许创建新的派送任务

#### 步骤4: Reschedule注意事项
1. 根据干线发车时间表选择合适的配送日期
2. 考虑前几次派送失败的原因
3. 更新订单备注说明reschedule原因
4. 如果是商业地址，确保安排在工作时间内配送

## 3. 关键控制点

### 3.1 时间控制
- 严格在13:15-13:30时间段内完成
- 优先处理时效要求高的订单

### 3.2 质量控制
- 确保订单ID正确更新
- 订单备注必须清晰说明reschedule原因
- 商业地址必须标注工作时间配送要求

### 3.3 系统操作
- 先在OR系统查找，找不到再用DMS辅助
- 更新旧订单ID为负数
- 保留历史记录便于追溯

## 4. 常见问题处理

### 4.1 OR系统找不到订单
**解决方案**: 使用DMS系统查询配送日期，然后在OR的规划路线中按日期查找

### 4.2 商业地址配送时间冲突
**解决方案**: 
- 确认客户营业时间
- 安排在工作时间内配送
- 在订单备注中特别说明
- 通知承运商注意配送时间

### 4.3 多次派送失败的订单
**解决方案**:
- 分析历史派送失败原因
- 联系客户确认地址和收货时间
- 考虑更换承运商
- 必要时联系李锐敏协助处理
